01

The simple path

⚡ TLDR — Simple path

Read this if you want to try the concept before committing to the full build. No code, no hosting, no developer accounts.

Minimum subscription needed

Claude Pro (~£17–18/month). That's it. You do not need Claude Code — that's a separate developer tool for the full build. The simple version is built entirely inside Claude's chat interface using a feature called Projects, which lets you upload documents Claude remembers across every conversation. No API key, no Vercel, no GitHub.

Free tier is not enough — it can't reliably run interactive AI-powered artifacts or store data across sessions. Pro is the minimum.

Documents to prepare before you prompt

Write these before you open Claude. The quality of your prep is the quality of your app.

Document 1 — About Me (most important)

  • The roles you play and what each demands of you
  • Your goals across each area — specific, not aspirational
  • Your daily structure: wake time, productive window, fixed commitments
  • Your professional background — 2–3 paragraphs on what you've actually done
  • The tone you want when you fail. The AI is only as honest as you license it to be.

Document 2 — App Spec (what you're building)

  • The tabs you want (e.g. Today, Hourly Check-in, Weekly Review, Goals)
  • The hours your day runs (e.g. 6am–10pm)
  • Scoring weights per life area — must add up to 100%
  • What the AI verdict must contain — specify exactly: what happened, where you lied to yourself, the one thing that changes everything
  • Non-negotiables about tone, structure, or timing

Where to upload the documents

  1. Go to claude.ai and sign in with your Pro account.
  2. In the left sidebar, create a New Project — name it something like "My Accountability App".
  3. Inside the Project, open Project Knowledge and upload both documents.
  4. Claude now has access to them in every conversation in that Project. No need to paste again.

What is the prompt?

Start a new conversation inside the Project and send something like this — edit the bracketed parts:

"Using the About Me and App Spec documents in this project, build me a single interactive artifact that works as my personal accountability app. It should have tabs for [list your tabs]. It should run hourly check-ins from [start hour] to [end hour]. Scoring weights are [your weights]. The AI verdict tone should be [your tone]. All my entries must persist in artifact storage so they're there when I come back — test this works before you consider it done. I will be using this on my phone browser, so it must be fully mobile-friendly."

After Claude builds the first version: click every tab, make a test entry, close the tab entirely, come back and check the entry is still there. If it isn't: "My entry from earlier isn't showing. Fix the persistence so data survives a tab close."

Limitations of the simple build

Phone works, but it's a browser tab — not an installed app. No home screen icon, no offline access, no reminders.
One device, one browser, one conversation. Entries don't sync across devices. Pick one, stay on it, bookmark the exact conversation.
You're renting, not owning. Data lives inside Claude's infrastructure. If you clear browser data or lose account access, entries may not survive. Ask Claude to add an Export button.
The UI adapts to mobile, but it's never truly full-screen. The artifact always renders inside the Claude chat interface. It will always feel like something living inside a chat, not a standalone app.
No push notifications. You'll need a separate alarm until you've built the habit.
Requires an active Claude Pro subscription. If you cancel, the app stops working.
If these limitations matter to you, the full build below solves all of them. The build itself is straightforward — it's the testing and iterating that takes time, not the setup.
02

The full build

This is what I actually run. It's an installed app on my iPhone home screen, my data sits on my own device, and an AI writes my verdicts via a direct API connection.

The setup is genuinely not complicated — Claude Code does most of the heavy lifting and you don't need to know how to code. What takes time is testing: finding edge cases, making sure data persists exactly as expected, and iterating until the app behaves the way your life needs it to. Budget for that, not for the build itself.

The build sequence — in order

Before writing any code, prep the same two documents from above (About Me + App Spec). The more precise the spec, the less rebuilding you do later.

  • 1
    Set up all accounts in one sitting.
    Create your Anthropic API key, Vercel account, and GitHub repository before anything else. The moment you have an API key, set a monthly spending cap — a bug in a loop can make thousands of API calls and you don't want to find out on your credit card statement.
  • 2
    Have Claude Code scaffold the app.
    Open Claude Code in your terminal, hand it your spec, and let it build the first version locally. Run it in your browser, click every tab, enter test data. It will look rough. That's correct — you're starting, not finishing.
  • 3
    Wire the AI features through a secure middle layer.
    Your API key must never live inside the app code. The right pattern: a serverless function on Vercel holds the key, and the app calls that instead of the API directly. Ask Claude Code explicitly: "Proxy the AI API calls through a Vercel serverless function so the key is never exposed in the client."
  • 4
    Build the Export button before anything else feels finished.
    Your data lives in browser storage on your device (IndexedDB). If you ever clear Safari's cache or get a new phone without exporting first, the data is gone. Build the Export button on day one, not when it's too late.
  • 5
    Test persistence properly, not optimistically.
    Make several entries across tabs. Close everything. Come back the next day. Still there? Clear the cache on desktop and hard-refresh — still there? Test on your phone too. This is where you should expect to spend the most time.
  • 6
    Deploy and install it on your phone.
    Push to Vercel. Open the URL on your phone. Use "Add to Home Screen" — a well-built web app installs and behaves almost exactly like a native one. This is the moment the project becomes a tool.
  • 7
    Establish a deploy ritual and write it down.
    Every time you update the app: build fresh → deploy with a force flag → hard-refresh on desktop → clear site cache on phone. Most "why isn't it updating?" confusion is a caching issue, not a real bug.
  • 8
    Connect your calendar last, as a bonus.
    Once the core loop works reliably, connecting Google Calendar lets the app see your real schedule and factor your actual time use into the verdict. The app is fully useful without it.

Honest limitations of the full build

Your data lives on one device. It doesn't sync automatically. Export regularly — if you lose entries because you didn't, that's on you, not the app.
Some platform features are flaky. Reliable push notifications on iOS can be inconsistent. A plain alarm works fine as a workaround.
You own it, which means you maintain it. No one pushes updates to this but you. That's the price of owning your data outright.

05

The part most people skip

The hard part of this was never the build. Claude Code did the heavy lifting and the setup is not the obstacle.

The hard part is the one-pager. Writing down, honestly, what you are actually trying to do with your life and exactly how harshly you want to be told when you are not doing it. The app is just a mirror. A mirror is only worth building if you are willing to look.

If you soften the tone because the savage version stings — you have built a more comfortable way to lie to yourself, and you would have been better off with nothing. Decide that before you start, not after.
